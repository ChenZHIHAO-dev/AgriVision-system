# AgriVision 数据来源与采集计划

检索与更新日期为 2026 年 11 月 17 日。目标是为南阳小麦、玉米、花生建立可训练、可追溯且便于扩充的图像数据集。“找到资源”与“已下载并通过许可、质量检查”分别记录。

## 本轮实际采用

- **D01 Kaggle v6**：压缩包约 6.54GB，元数据标注 CC0；本地 14,154 张图像文件，选取、去重和冲突处理后入模 6,315 张。四个核心类别加 other，具体划分见[模型说明](model-card-wheat-v1.md)。
- **D03 JIC 公开子集**：999 张，CC BY 4.0，MD5 校验完成；771 张与主数据重复或近重复，排除后剩 228 张 Septoria。不能将这两库数量直接相加，也不能据此宣称跨来源四类验证。
- **手动试用照片**：另从 Wikimedia Commons 保存 10 张署名许可照片，核对寄主和拍摄内容并排除发现的重复；不加入训练、阈值选择或模型评分，未预先运行识别。每张来源、许可和参考说明在本地 `data/manual-tests/wheat-real-photos/参考标签与来源.csv`。

聚合数据页的 CC0 声明不能自动覆盖原始来源的许可；已发现与 CC BY 4.0 的 JIC 重叠，需要保留署名并继续逐源核对。当前为开发训练，不将数据打包发布。

## 获取优先级与规模目标

D01、D03 的本轮下载和去重已完成。后续优先补足南阳独立田间样本，再核对 D06、D07、D08 的版本与来源。D04、D05、D09 补充中国田间和区域重点病害，按实际访问与许可结果接入。D02、D03 完整库以及 D10 的申请不在本轮自动发送。

首批总体目标为去重后约 1 万至 3 万张适配目标任务的独立图像，这是采集目标，不是现有库存。每个核心类别争取 500 至 2,000 张独立图像；不足时增加采集或减少首批类别。完成目标不以合并不适用病害或重复增强图来凑数。

首轮另留 300 至 600 张独立实拍图作为现场验证目标，逐步扩大来源、设备和拍摄批次。数据少的类别明确记录覆盖不足；通过拍摄实践和模型错误分析决定下一轮补什么。

## 标签与数量口径

每张图像保存来源、版本、原文件路径、校验值、感知哈希、原图标识、作物、器官、病虫害、拍摄地区、拍摄时间及标签复核状态。来源未知的字段保留未知，不通过猜测补齐。

使用稳定的内部标签，并维护原标签到内部标签的映射。关键区别包括：

- 小麦条锈病与叶锈病分别标记；小麦赤霉病的麦穗照片另设器官。
- 玉米普通锈病与南方锈病分别标记；PlantVillage 的 Common rust 不改名为南方锈病。
- 花生早晚叶斑病在合并来源中保留合并标签，不凭文件名拆分。
- 多标签图保留所有已确认标签，或交由人工挑选适合单标签任务的样本。
- 灰斑病、大斑病、小斑病与泛称 leaf blight 的映射需核对原始定义。

同一原图产生的裁剪、旋转和颜色增强图归于同一个原图组。统计同时给出下载文件数、独立原图数、目标类别数、有效图数及排除原因，避免把这些口径相加。

## 数据处理和评测

1. 固定下载来源和版本，保存数据说明、许可文本、获取日期及文件校验值。
2. 检查解码失败、过小图片、截图拼图、明显错标和重复；用感知哈希与特征相似性查找跨来源近重复。
3. 抽查每类图片，重点复核易混类别；源数据的地区和背景差异作为评测维度保留。
4. 先按地块、拍摄批次、同叶同株与原图组分组，再划分训练、验证和测试。建议起点为 70%、15%、15%，以可用分组情况调整。
5. 在训练阶段在线增强。验证和测试保留真实图像分布；模型阈值只用验证集选择。
6. 保留整套来源或本地实拍作为外部测试。查看每类召回率、Macro-F1、混淆类别与错误图片，而非只看总准确率。
7. 增加非目标作物、非植物、药害、缺素、混合症状、模糊与过远图片，验证系统是否能提示信息不足或未支持。

首次下载先预留约 30 至 60GB 工作空间，再按具体来源调整。D05 论文中的约 200GB 是整库口径，需先核实是否可按作物获取。原始图优先留在本地数据目录，适配后的训练图另存；数据增强尽量在线完成。

## 南阳实拍如何补齐

按作物和生育期采集近照、叶背、整株、田间分布；发现根茎或穗部异常时补拍对应器官。保留健康、早期、典型症状和易混情况，每一批记录地块、日期、设备与农技人员判断。

本地实拍分为独立验收集和后续训练集。已经用于最终验收的图像固定版本；若之后回流训练，应建立新的独立验收批次，并记录这个变化。

## 农技知识与产品数据

图像数据用于识别训练；农业资料与产品标签用于解释和用药匹配，两者分别维护。

首批知识来源优先南阳市农业农村局、河南农技机构和全国农技中心。产品资料优先经核对的登记与标签，加上公司现有产品目录、适用方案及维护记录。普通网页上的配方只有在来源与适用性核对后，才进入可提供给用户的方案库。

大型公开数据集、Plantix 等产品界面与商业 API 是不同的资源。产品可用于交互参考；使用其数据或接口需遵循其提供的具体条款，不能由可访问页面推定训练或再分发权限。
