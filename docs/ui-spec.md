# AgriVision 网页与微信小程序交互规范

设计面向田间农户和农资门店人员，优先完成拍照、理解结果、补充信息、查看建议和找回问诊五项任务。手机便于单手操作，电脑便于看图与连续咨询；两端使用一致的业务名称和结果结构。

## 参考与设计原则

[Plantix](https://www.plantix.net/en/) 的产品资料展示了拍照诊断、处理建议与知识服务的连接；[PlantVillage Nuru 的大学介绍](https://sites.psu.edu/agsciresearch/at-a-glance/nuru-and-plantvillage/) 说明了田间离线场景的价值。本项目借鉴其任务顺序，首版采用本机服务推理，离线能力后续单独验证。

组件交互参考微信团队的 [WeUI](https://github.com/Tencent/weui)；选项展示参考 [Ant Design Select](https://ant.design/components/select-cn/) 与 [Radio](https://ant.design/components/radio-cn/)；多屏布局参考 Google 的[自适应界面说明](https://developer.android.com/develop/adaptive-apps/guides/get-started-with-adaptive-apps)。这些是设计参考，前端仍按 uni-app 的实际组件能力实现。

少量互斥选项平铺便于比较，多选项和层级数据使用选择器。大屏改变信息组织方式，保留列表与详情的并列空间；小屏一次展示一个主要任务。

## 页面与导航

手机底部导航为“识别、记录、知识”三个入口。“继续咨询”属于当前问诊结果，点击后进入带有该问诊摘要的对话页；新建问题时创建新问诊。设置放在次级入口中。

| 页面 | 手机布局 | 电脑布局 |
| --- | --- | --- |
| 识别首页 | 地区、三个作物选项、大拍照入口、相册入口、最近记录 | 左侧导航，中心上传区域，右侧最近记录与支持范围 |
| 图片确认 | 原图预览、作物确认、必要信息、一个“开始识别”按钮 | 左图右表单，补充信息可展开 |
| 问诊结果 | 疑似结果、下一步、方案与依据逐段展示；底部继续咨询 | 左侧照片与问诊信息，右侧结果和建议；点击来源展开侧栏 |
| 对话 | 固定问诊摘要、消息流、快捷回答与输入框 | 历史列表、当前对话和可折叠图片详情 |
| 历史记录 | 按时间排序，显示作物、缩略图和状态 | 列表与问诊详情并排，支持搜索和筛选 |
| 知识与产品详情 | 作物分类、知识卡、来源、适用产品资料 | 目录与详情并排，长文保持合适阅读宽度 |

首屏突出“拍照识别”和“从相册选择”。已有作物或地区偏好可回填，用户可直接修改。小麦默认首个可见选项，不把未确认的默认值当作用户的明确选择。

## 控件选择规则

| 信息或动作 | 控件 | 行为要求 |
| --- | --- | --- |
| 小麦、玉米、花生 | 平铺单选卡片或分段选择 | 三个选项直接可见；显示实际识别支持状态 |
| 省、市、县 | 级联选择器；手机底部面板 | 可预填河南、南阳，并允许更改；区县可选 |
| 生育期 | 随作物变化的单选选择器 | 手机用底部单选面板；保留“不清楚”，切换作物后清除不适用值 |
| 叶片、麦穗、茎基部、虫体 | 少量选项平铺 | 根据问题显示；选择后改变拍摄提示 |
| 多个可见症状 | 多选标签或复选框 | “不清楚”与具体症状互斥，可补充文字 |
| 最近施药时间 | 日期选择器或明确的相对时间选项 | 支持“不记得”，保留原始描述 |
| 已用药剂或公司产品 | 可搜索选择器，允许填写未收录产品 | 选中后展示含量和剂型，重名产品不自动合并 |
| 面积、药液量等数值 | 带单位的数字输入 | 单位可见，验证范围；只在方案需要时询问 |
| 拍照与相册 | 主按钮与动作面板 | 手机触发系统能力；电脑上传支持点击与拖放 |
| 来源、标签与更多资料 | 展开区或详情页 | 保留可读标题和来源；关键结论不依赖展开 |
| 删除记录 | 低强调动作与确认 | 说明具体删除哪条记录，与日常主操作保持距离 |

单选卡片、导航、标签与按钮有各自用途。选择作物用于设置值，“开始识别”用于提交；不通过点击作物卡片直接触发上传或跳转。

## 问诊中的信息节奏

提交前只要求图片和作物，地区可沿用已确认值。生育期、近期施药、症状分布等信息根据识别与建议需要逐步补问，避免第一次使用就填写长表单。

结果先显示疑似问题和下一步。防治步骤、产品方案及来源按内容层级展开；公司商品在适用性核对后出现。需要补拍时，补拍成为当前主操作，替代直接用药按钮。

产品方案页保持药名、含量剂型、适用对象、用量单位、施用方式和依据一致。前端直接渲染后端返回的结构化方案字段，解释文字与方案卡片关联。

## 视觉样式建议

以下数值是本项目建议的设计变量，实施后用实际页面检验。

| 项目 | 建议 |
| --- | --- |
| 主色 | 深绿 `#176B45`，用于主要动作和选中状态 |
| 背景与表面 | 浅暖灰 `#F6F8F5` 与白色 `#FFFFFF` |
| 正文与辅助文字 | 正文 `#18352B`，辅助信息 `#52645A` |
| 状态颜色 | 橙色提示待补充，红色用于阻断错误；同时配合图标和文字 |
| 字体 | 系统中文字体；手机正文约 16px，辅助约 14px，主要标题约 22px；桌面标题可至 28px |
| 间距 | 以 8px 为基础，常用 8、16、24、32px；表单标签与输入保持统一间距 |
| 触控 | 主要按钮高度约 48px，常用触控区域至少 44px，留足相邻间距 |
| 容器 | 适量 12 至 16px 圆角、轻边界，统一卡片和输入框层级 |
| 图标与图片 | 一套线性图标，关键动作附文字；原图可放大查看症状细节 |
| 动效 | 简短过渡与真实任务状态，尊重减少动画设置 |

避免大面积装饰占据拍照入口。药品信息采用清楚的文字与单位，农作物图片用于帮助理解对象，长段内容保持正常阅读宽度。

普通文字与背景对比度以至少 4.5:1 为目标，大字号文字至少 3:1；选中、错误和待补充状态同时用文字表达。[W3C 对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 响应式布局

建议网页在窄屏使用单列；约 768px 起尝试分区，约 1024px 起采用导航加双栏，主要内容最大宽度约 1280px。断点以实际内容是否拥挤调整，不直接按设备型号判断。

小程序保留原生导航和底部安全区，输入框避让键盘；对话滚动到新内容时不抢走用户正在查看的位置。桌面支持键盘操作与可见焦点，上传区也能通过按钮访问。

同一作物、问诊和图片选择在布局变化后保留。手机使用相册或拍照，电脑使用文件上传；界面文字随实际能力变化，不展示不可用操作。

## 文案和状态

| 情况 | 文案示例与动作 |
| --- | --- |
| 等待图片 | “拍一张有症状的叶片，尽量拍清病斑。”提供拍照和相册入口 |
| 图片过远 | “叶片细节不够清楚，请靠近后重新拍摄。”保留原图与重新选择 |
| 需要叶背 | “再补一张叶背近照，有助于区分当前候选。” |
| 疑似结果 | “疑似小麦条锈病”，下接需要核实的信息和下一步 |
| 未见支持类别症状 | “未发现已支持病害的明显特征”，提示补充异常情况 |
| 未支持类别 | “当前模型还不能可靠判断这类情况”，展示补拍与资料咨询路径 |
| 没有适用产品 | “暂未匹配到资料完整、适用于当前情况的产品”，保留防治说明 |
| 对话超时 | “建议暂时未生成，可以重试。”保留已获得的图片识别结果 |
| 历史为空 | “你的识别与咨询记录会保存在这里。”提供开始识别按钮 |
| 演示样例 | 明确标注“演示样例”，与真实模型处理结果区分 |

上传进度可展示实际百分比；识别、检索、生成建议显示真实阶段状态，不制造进度或准确率。模型分数需要时放在详情中，不写成病害确诊概率。避免“100% 确诊”“保证治愈”等表述。

“识别中、待补充、结果可查看、需复核”在记录列表和详情页一致。提交按钮防止重复操作；返回页面保留图片和已填信息；允许重试失败步骤。

## 原型与交付验收

先制作移动端和桌面端的首页、图片确认、结果、对话四组关键原型，再统一组件样式并实现两个编译端。原型与代码都覆盖正常、加载、空白、失败、需补充和未支持状态。

用真实任务检查：首次拍照获得结果、补一张照片、修改错误作物、询问用药、查看来源、找回历史记录。观察是否出现误触、回不去、重复填写、找不到按钮或误解结果等问题。

网页至少检查 375、390、768、1280、1440px 宽度，以及键盘操作和字体放大；小程序在开发者工具与手机真机分别验证拍照、相册、返回、键盘和网络恢复。视觉验收同时检查留白、文字层级、对比度、长药名换行和剂量单位。
