# 第一版问诊交互约定

更新：2026-11-17。先完善功能与交互，不继续训练或调整模型阈值。

## 功能关系

拍照是特色入口，咨询是可重复进入的独立聊天窗口。两者共享同一条问诊会话，照片不会在转入聊天时丢失；照片识别也可以在聊天中调用。

手机底部为首页、拍照、我的三等分，相机在正中；拍照页顶部保留独立咨询入口；参考资料收进我的。相机打开作物选择及拍照 / 上传；咨询恢复当前会话，或打开最近的已登录咨询。“新建咨询”和历史位于电脑侧栏、手机左上角抽屉。外观只在设置中选择。

| 用户操作 | 程序执行 | DeepSeek | 显示 |
| --- | --- | --- | --- |
| 选择作物 | 更新照片作物信息 | 不调用 | 作物选中状态 |
| 拍照或上传 | 检查文件与画质，独立 CNN 识别，检索本地知识 | 不调用 | 真实照片的扫描加载效果，完成后显示照片、结果、候选分数和简要建议 |
| 独立拍照完成 | 生成本地上传记录与识别摘要，加入同一问诊 | 不调用 | 结果页；底部固定“继续对话” |
| 点击继续对话 | 打开原问诊聊天，带入上传记录和识别摘要 | 不调用 | 已有内容的聊天窗口 |
| 基本信息不足时提问 | 程序返回固定信息选择卡 | 不调用 | 作物 / 生育期选项，可以选择暂不确定 |
| 选择基本信息 | 更新问诊上下文，不伪造用户发言 | 不调用 | 选项更新；由用户决定是否继续回答 |
| 点击发送 / 回答刚才的问题 | 组合文字、结构化识别回执、知识及资料摘录 | 调用所选模型 | Markdown 回答与资料来源 |
| 聊天中添加照片 | 逐张识别并加入待发送照片 | 不调用 | 处理回执及附件缩略图，可继续添加 |
| 移除待发送照片 | 删除尚未用于聊天的照片及其候选记录 | 不调用 | 更新剩余图片的结果 |
| 查阅历史 | 按登录账户读取服务端记录 | 不调用 | 恢复原问诊及聊天内容 |

应用默认进入拍照页；首页只提供拍照跳转与最近记录。拍照页提供作物选择、相机、相册和咨询入口。

## 结果页与聊天页

结果页呈现照片、初步病害标签、单图候选分数和简要知识建议，固定显示继续对话按钮。纯文字咨询不出现空的结果页。聊天页提供按需查看识别结果的入口，取消常驻的“结果与建议 / 继续咨询”双标签。

照片上传记录与识别摘要由程序生成，来源为 recognition，不冒充 DeepSeek 的回答，也不消耗对话 API。它们说明用户实际执行的上传动作，不伪造田间观察。

## 多图与不确定情况

每张图片保留独立结果、候选分数、模型版本和画质状态，整组不计算平均概率，也不按多数票选病害。

- 相同病害：归纳一致线索，保留逐图记录。
- 一部分识别、一部分未知或需补拍：保留已识别线索，明确其余未判明。
- 不同病害：分别说明候选，询问是否同一株或同一地块，不强行合并。
- 健康参考：只表示未见已支持病害的明显特征，不能排除其他问题。
- 不同模型版本：先统一重试，再比较，原版本记录继续保留。
- 无标签、质量不足、模型未开放、服务错误：均返回明确回执，不说软件未收到照片。

分类分数用于比较本版候选类别，不等于田间确诊概率。没有图像症状描述时，文本模型只能建议用户核对典型症状，不能声称看到具体颜色或斑点。

## 账户与隐私

访客只保留当前临时会话和照片，位于服务端内存，30 分钟无活动过期；不写历史数据库或图片文件。登录不会自动迁入访客内容。

登录后的问诊按服务端身份保存，客户端提交的会话标识不能冒充其他账户。账号提供器仍为开发内存版，admin 为固定测试身份；注册账号和登录令牌在服务重启后失效。业务记录保存于服务器本地 SQLite，正式账户数据库、云端部署与同步仍待接入。

## 界面与后续

浅色使用微灰背景；深色使用中性灰黑。按钮按压使用当前主题的浅一档底色，覆盖框架默认白色按压效果。下拉选择使用统一浮层 / 底部面板。聊天框采用有上限的原生多行输入，长内容框内滚动；移动键盘弹出时收起底部导航。

知识页支持知识库 / 农业资讯与网格 / 列表。资讯当前为有真实来源、原文日期的精选链接；自动采集、定期更新和管理审核留待后续，界面不宣称已实时抓取。

参考：[Apple 色彩](https://developer.apple.com/design/human-interface-guidelines/color)、[深色模式](https://developer.apple.com/design/human-interface-guidelines/dark-mode)、[按钮](https://developer.apple.com/design/human-interface-guidelines/buttons)。

实测修正：补充生育期后，最新回执同时传递已确认的 context，并为原先未填写生育期的图片使用本次信息；已经明确的历史拍摄阶段仍保留。已完成的信息收集提示不再送入对话模型，服务端也移除简单的重复生育期询问。
