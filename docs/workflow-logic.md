# 识别与咨询功能逻辑 · 第一阶段

更新：2026-11-17。先验证软件功能与状态流转，再迭代识别效果；当前不继续调阈值或重训。

## 两个入口

**拍照识别**：选择作物与照片 → 每张独立画质检查与分类 → 展示逐张结果、整组归纳 → 从本地知识库给简要建议。此入口不调用 DeepSeek。

**智能咨询**：可从文字开始，也可沿用识别记录 → 补问必要种植信息 → 将结构化识别回执和检索到的资料文字传给 DeepSeek → 给出解释与追问。原图不发送给对话模型。联网检索为用户显式开启的独立能力，没搜索时不能自称联网查询。

## 每张照片的回执

上传成功、画质检查通过、得到可用的分类结果、得到可靠病名是四件不同的事。每张图保存自己的作物、生育期、处理状态、候选分数、模型版本与处理时间，不只保留最后一张。

| 结果 | 用户应看到 | 后续操作 |
| --- | --- | --- |
| 支持范围内的初步结果 | 第几张提示疑似哪种病，或未见已支持病害明显特征 | 对照症状并阅读资料 |
| 分数不足 | 照片已收到，目前无法可靠判断 | 补拍和补充症状信息 |
| 其他 / 未覆盖症状 | 照片已收到，可能不在当前支持范围 | 不强造病名，继续记录、复核 |
| 画质不足 | 照片已收到，列出尺寸 / 光线 / 清晰度问题 | 有针对性地补拍 |
| 模型未就绪 | 照片已保存，当前作物暂无可用模型 | 可以先做文字资料咨询 |
| 服务异常 | 照片已保存，本次识别未完成 | 重试，不解释成没有病害 |

对话必须以最新回执为准，不能因为 DeepSeek 没收到原图就说用户没有上传图片。已有识别结果时，要引用该结果；旧对话里的错误表述不能覆盖新结果。上传参数中的“生育期不清楚”占位值不覆盖已经填写的生育期，明确选择“暂不确定”时才表示用户暂不填写。

## 多图归纳

一次问诊先限定同种作物、同次田间观察；不同作物应新建问诊。照片可以是同株 / 同地块的不同部位和角度。

| 多图情况 | 整组处理 |
| --- | --- |
| 有病害线索，其余未判明 | 保留病害线索，显示支持图片编号和未判明数量；后者不把前者清零 |
| 多张支持同一病害 | 归纳为一致线索，显示张数；不计算“整组确诊概率” |
| 病叶与未见已支持病害特征的叶片并存 | 保留病害线索，明确照片之间的差异；不以多数正常叶排除少数病叶 |
| 不同图片提示不同病害 | 并列候选与对应图片，询问是否混拍、是否同一观察对象；不自动选最高分或平均 |
| 只有部分图片未见已支持病害，其余不确定 | 不把整组判为健康，仍需核对未判明照片 |
| 全部不确定 / 画质不合格 / 无模型 / 异常 | 按逐图原因给出排查、补拍或重试建议 |
| 模型版本或作物混杂 | 不合并分数，明确提示需要按统一条件重新核对 |

每张的模型分数仅用于该张候选比较。图像可能高度相关，也可能包含不同部位，不能把分数直接取均值当作整组患病概率。知识库建议只引用已支持的线索；冲突时不自动匹配具体产品方案。

## 第一阶段验收

- [ ] 单独识别只调用视觉模型和知识库。
- [ ] 一张识别成功后再加不确定图，原线索仍保留。
- [ ] 不同疾病线索并列，逐张可追溯，不平均。
- [ ] 全部不确定、画质不足、模型异常均有明确回执。
- [ ] 继续咨询能引用最新识别与多图归纳，不重复声称没有收到图片。
- [ ] 已填作物 / 生育期不被占位值抹除，不重复补问。
- [ ] 模型菜单、资料附件、浅深主题与手机布局一致。
- [ ] 本机完成真实图像与 DeepSeek 调用联调，结果记录在 README。
