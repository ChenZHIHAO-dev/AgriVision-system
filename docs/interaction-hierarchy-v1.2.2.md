状态：78/79 项完成，已发布。F08 实际手机键盘、相机权限、微信真机与设备返回验证待办。日期：2026-11-18。基线：main / 9d36983，线上前端 a18c312。

## 目标与层级

本轮先修复父子页面关系和待回答问题恢复，再统一视觉反馈；不重新训练模型，不扩展主导航功能。

| 层级 | 内容 | 进入 | 返回/关闭 |
| --- | --- | --- | --- |
| L0 主页面 | 首页、拍照、我的 | 底部导航/桌面窄导航 | 保留问诊数据和草稿 |
| L1 结果窗口 | 本次照片、逐张识别、简要建议 | 拍照完成/查看本次识别 | 回到拍照页 |
| L1 或 L2 聊天 | 问题、识别摘要、后续回答 | 拍照页咨询/结果继续对话/历史 | 回到进入它的父级 |
| 聊天上的详情 | 识别结果、问诊信息 | 聊天顶部按钮 | 回到同一聊天，不清空输入 |
| 辅助窗口 | 登录、图片来源、信息编辑 | 所在页面动作 | 回到触发位置 |
| 我的子页面 | 设置 | 我的设置 | 返回我的 |
| 首页资料详情 | 参考资料正文 | 首页参考资料 | 返回首页资料栏目 |

主页面选择不删除数据；同一主导航再次点击不重置。结果与聊天共用同一个 case，照片入口和文字入口并行，图片始终先由独立视觉模型处理。聊天里的识别详情是查看动作，不重跑模型。

## 状态与调用规则

1. 仅有选择/编辑信息：保存上下文，调用模型次数为零。
2. 用户发送问题但缺基本信息：保存原问题与附件标识，返回程序问题选项。
3. 补齐最后信息：恢复同一待回答问题，只生成一条助手回答。
4. 重复恢复同一标识：返回已完成结果，不再次调用模型。
5. 新问题覆盖旧待回答意图；用户文字补充生育期仍归于旧问题。
6. 访客问诊和待回答问题仅在服务端内存暂存，不进入账户历史。

- [Apple：Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars)：侧栏与内容区域组织参考。
- [Lucide Static](https://lucide.dev/guide/static)、[许可](https://lucide.dev/license)：统一线性图标与许可来源。
- [uni-app image](https://uniapp.dcloud.net.cn/component/image.html)：跨端图片资源能力与限制。
